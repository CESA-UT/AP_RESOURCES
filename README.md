# AP_RESOURCES

مخزن `AP_RESOURCES` برای جمع‌کردن منابع آموزشی موردنیاز تمرین `AP_1404_PRACTICE_ONE` ساخته شده است. اینجا قرار نیست یک کتاب کامل C++ یا یک فهرست بی‌انتها از لینک‌ها داشته باشیم. هدف این است که وقتی وسط حل تمرین به یک مفهوم، ابزار یا تصمیم فنی برخوردید، سریع به یک منبع کوتاه، دقیق و مرتبط برسید.

این repository پابلیک می‌ماند تا دانشجوهای ورودی های بعدی هم بتوانند از آن استفاده کنند، آن را کامل‌تر کنند و تجربه‌های خودشان را به آن اضافه کنند.

## این مخزن چطور استفاده می‌شود؟

- لازم نیست همه منابع را از اول تا آخر بخوانید.
- اول خود تمرین را شروع کنید.
- هرجا گیر کردید، فقط سراغ topic مربوط به همان نیاز بروید.
- اگر منبع خوبی پیدا کردید یا خودتان یک توضیح مفید نوشتید، آن را به مخزن اضافه کنید.
- حتی یک متن کوتاه که با کمک ChatGPT نوشته شده هم قابل قبول است، اگر دقیق، مفید و مرتبط با تمرین باشد.
- اگر منبعی فراتر از نیاز مستقیم این تمرین است، اضافه‌کردنش مشکلی ندارد؛ فقط باید واضح برچسب بخورد که `مطالعه اضافه` است و برای حل مستقیم تمرین الزامی نیست.
- اگر منبع اصلی بیرون از GitHub است، باید یک نسخه قابل‌خواندن از آن به‌صورت `markdown`، `pdf` یا فایل مشابه داخل خود repository قرار بگیرد و لینک اصلی resource به همان فایل داخلی اشاره کند.

## فلسفه پروژه

این تمرین از روی `README` پروژه اصلی، بیشتر از همه به این موضوع‌ها نیاز دارد:

- طراحی شی‌گرا و کلاس‌بندی تمیز
- مدیریت حافظه و کپی درست داده‌ها
- ذخیره‌سازی اطلاعات
- Git و GitHub برای کار گروهی و تحویل فازها
- Build system و ساختار فایل‌های C++
- طراحی ماژولار برای توسعه فازبه‌فاز
- اعتبارسنجی، تست، debug و اجرای پایدار
- هش‌کردن رمز عبور و نکات پایه امنیتی
- اجرای همزمان ساده و سالم‌ماندن داده‌ها
- GUI به‌عنوان مسیر اختیاری

پس ساختار این مخزن هم بر همین اساس چیده شده است.

## راهنمای استفاده برای دانشجوها

1. تمرین را بخوانید و فاز اول رو شروع کنید.
2. اگر به یک سؤال واقعی رسیدید، topic مربوطه را باز کنید.
3. از `README.md` هر topic بفهمید آن بخش برای این تمرین دقیقاً به چه درد می‌خورد.
4. از `resources.md` یک منبع کوتاه و مناسب انتخاب کنید.
5. اگر فایل واقعی منبع لازم بود، به پوشه `files/` همان topic بروید.
6. اگر چیزی کم بود، با `template.md` همان topic یک منبع جدید اضافه کنید.

## راهنمای مشارکت

- برای قوانین ساده مشارکت، فایل [CONTRIBUTING.md](/home/reza/dev/ut/AP_RESOURCES/CONTRIBUTING.md) را ببینید.
- برای قالب استاندارد منبع، فایل [index.md](/home/reza/dev/ut/AP_RESOURCES/index.md) و template هر topic را ببینید.
- اگر هنوز منبع آماده ندارید، می‌توانید یک issue از نوع request یا suggestion باز کنید.

## مکانیزم پیشنهادی برای بالا آمدن منابع بهتر

1. هر منبع در `resources.md` با یک شناسه کوتاه ثبت شود.
2. برای هر topic یک فایل `ranking.md` جدا وجود دارد.
3. اگر repository بخش Discussions داشته باشد، برای هر topic یک discussion یا thread ساخته می‌شود و رأی‌ها و بازخوردها در رتبه‌بندی اثر می‌گذارند.
4. برای درخواست یا پیشنهاد منبع، از GitHub Issue با labelهایی مثل `resource-suggestion` و `resource-request` استفاده می‌شود.
5. یک GitHub Actions workflow فایل‌های رتبه‌بندی topicها را می‌خواند و [ranking.md](/home/reza/dev/ut/AP_RESOURCES/ranking.md) را به‌صورت مرکزی بازسازی می‌کند.
6. منابع `تأیید TA`، منابعی که استفاده بیشتری شده‌اند، و منابعی که بازخورد بهتری گرفته‌اند بالاتر قرار می‌گیرند.

## قوانین کیفیت منابع

- باید به یک نیاز واقعی در همین تمرین وصل باشد.
- باید کوتاه و هدفمند باشد.
- باید مشخص کند چه زمانی باید سراغش برویم.
- اگر لینک خارجی می‌دهد، بهتر است کنار آن یک خلاصه کوتاه فارسی هم داشته باشد.
- اگر منبع اصلی روی سایتی بیرون از GitHub است، باید خلاصه یا بازنویسی قابل‌استفاده آن داخل repo موجود باشد.
- اگر متن با AI تولید شده، باید توسط اضافه‌کننده بازبینی و اصلاح شده باشد.
- اگر با AI تولید یا تکمیل شده، باید ابزار، مدل و نوع استفاده به‌صورت شفاف ذکر شود.
- اگر منبع مستقیماً برای این تمرین نیست، باید با برچسب `مطالعه اضافه` مشخص شود.
- منبعی که کلی، پراکنده یا نامرتبط باشد مناسب این مخزن نیست.
