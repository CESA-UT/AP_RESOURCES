# راهنمای collaboration در GitHub

این خلاصه برای استفاده از GitHub در پروژه‌های گروهی کلاسی است.

## Pull Request

- PR جایی است که تغییرات قبل از merge دیده و review می‌شوند
- بهتر است هر feature مهم از طریق PR وارد branch اصلی شود

## Merge Conflict

- وقتی دو تغییر با هم رقابت می‌کنند، conflict رخ می‌دهد
- باید نسخه نهایی معنی‌دار بسازید، نه فقط markerها را حذف کنید

## روی GitHub چه چیزهایی ساده‌تر است؟

- دیدن diff
- review
- comment
- PR discussion

## چه چیزهایی بهتر است local حل شوند؟

- conflictهای پیچیده
- build و test
